## cp-note-000087

**Pergunta**

Como usar blocos consecutivos de caracteres iguais para tornar uma string binária alternada com o mínimo de remoções? Por que contar zeros e uns globalmente não resolve?

**Resposta**

Divida a string em blocos máximos de caracteres iguais. Dentro de um bloco de tamanho L, no máximo um caractere pode permanecer numa subsequência alternada: entre dois caracteres daquele bloco não há um símbolo diferente que possa separá-los. Portanto são necessárias pelo menos L-1 remoções.

Manter exatamente um caractere de cada bloco atinge esse limite, pois os blocos vizinhos têm símbolos diferentes por definição. Se há B blocos e N caracteres, a resposta é N-B, ou a soma de L-1. Por exemplo, 00111 tem blocos 00 e 111: são 1+2=3 remoções, e a subsequência 01 é ótima.

As strings 0011 e 0101 têm as mesmas frequências, mas exigem respectivamente 2 e 0 remoções. A informação relevante é a posição dos blocos, não só a frequência total. O laço com intervalo [i,j) processa também o último bloco sem precisar de um flush separado.

```cpp
vector<int> comprimentosDosBlocos(const string& s) {
    vector<int> blocos;
    for (int i=0;i<(int)s.size();) {
        int j=i;
        while (j<(int)s.size() && s[j]==s[i]) ++j;
        blocos.push_back(j-i); i=j;
    }
    return blocos;
}
int minimoRemocoes(const string& s) {
    int total=0;
    for (int tamanho:comprimentosDosBlocos(s)) total+=tamanho-1;
    return total;
}
```

**Complexidade:** O(N) de tempo e O(B) de espaço para explicitar os blocos. É possível acumular sem guardar o vetor, usando O(1) auxiliar.

**Critérios de acerto**

- Provar o limite de um sobrevivente por bloco original.
- Mostrar uma construção que mantém um por bloco e atinge o limite.
- Processar o bloco final e distinguir frequência de consecutividade.

## cp-note-000088

**Pergunta**

Em Make it Alternating, por que as escolhas ótimas de posições que permanecem são o produto dos tamanhos dos blocos? Por que caracteres iguais não tornam essas escolhas uma só?

**Resposta**

Após fixar o número mínimo de remoções, exatamente uma posição de cada bloco original deve sobreviver. Um bloco de tamanho L oferece L escolhas de posição. As escolhas de blocos diferentes são independentes; pelo princípio multiplicativo, existem L1*L2*…*LB escolhas de sobreviventes. Somar os tamanhos contaria escolher uma posição de apenas um bloco, em vez de escolher uma em cada bloco.

Em 00111, há 2*3=6 escolhas de posições, embora todas produzam a mesma string final 01. O problema distingue operações pelos índices escolhidos, não só pelo texto final. Escolher sobreviventes determina quais posições originais serão removidas.

Este produto conta apenas os conjuntos de posições removidas; ainda falta contar a ordem das remoções, tratada no card do fatorial. Aplique o módulo após cada multiplicação para que o acumulador continue limitado.

```cpp
long long escolhasDeSobreviventes(const string& s) {
    const long long MOD=998244353;
    long long escolhas=1;
    for (int i=0;i<(int)s.size();) {
        int j=i;
        while (j<(int)s.size() && s[j]==s[i]) ++j;
        escolhas=escolhas*(j-i)%MOD;
        i=j;
    }
    return escolhas;
}
```

**Complexidade:** O(N) de tempo e O(1) de espaço auxiliar. O produto intermediário cabe em long long sob N≤200.000 e acumulador reduzido pelo módulo.

**Critérios de acerto**

- Usar multiplicação para escolhas independentes em todos os blocos.
- Distinguir posições originais de strings finais iguais.
- Reconhecer que este produto ainda não conta as ordens de remoção.

## cp-note-000089

**Pergunta**

Por que o número de sequências mínimas de remoção é (produto dos tamanhos dos blocos) × D!, com D remoções? Por que não basta multiplicar os fatoriais de cada bloco?

**Resposta**

Primeiro escolha qual posição original permanece em cada bloco: há produto(L) escolhas. Para cada escolha, há D posições originais distintas a remover. Elas podem ser removidas em qualquer uma das D! ordens, porque apenas a string final precisa ser alternada.

Os índices mudam durante as remoções, mas isso não invalida a contagem: cada ordem de posições originais determina uma sequência única de índices atuais. Reciprocamente, acompanhando os índices atuais a partir da string original, reconstruímos exatamente quais posições foram removidas e em qual ordem. Essa correspondência evita tanto perder sequências quanto contar a mesma sequência duas vezes.

Usar só produto((L-1)!) contaria ordens internas aos blocos, mas perderia as intercalações de remoções entre blocos diferentes. Em 0011, escolhemos sobreviventes de 2*2 formas e podemos ordenar as 2 remoções de 2! formas: são 8 sequências. Se D=0, há uma sequência vazia; 0!=1, não zero.

```cpp
pair<int,long long> alternarComContagem(const string& s) {
    const long long MOD=998244353;
    int remocoes=0;
    long long escolhas=1;
    for (int i=0;i<(int)s.size();) {
        int j=i;
        while (j<(int)s.size() && s[j]==s[i]) ++j;
        int tamanho=j-i;
        remocoes+=tamanho-1;
        escolhas=escolhas*tamanho%MOD;
        i=j;
    }
    long long fatorial=1;
    for (int i=2;i<=remocoes;++i) fatorial=fatorial*i%MOD;
    return {remocoes,escolhas*fatorial%MOD};
}
```

**Complexidade:** O(N+D)=O(N) de tempo e O(1) de espaço auxiliar. Em todos os testes, a soma dos comprimentos é no máximo 200.000.

**Critérios de acerto**

- Separar a escolha das posições da ordem das operações.
- Justificar a correspondência apesar da mudança dos índices.
- Contar intercalações entre blocos e preservar 0!=1.

## cp-note-000090

**Pergunta**

Como calcular e reutilizar fatoriais módulo M em problemas de contagem? Por que reduzir só no final estoura, e por que f[0] deve começar em 1?

**Resposta**

Para módulo positivo, vale (a*b)%M=((a%M)*(b%M))%M. Calcule f[i]=f[i-1]*i%M a cada passo, mantendo o acumulador limitado. Calcular primeiro o fatorial inteiro e aplicar %M depois falha porque o inteiro pode estourar muito antes da operação de módulo.

O produto vazio vale 1: por isso f[0]=1 representa a única ordem de um conjunto sem operações. Em Make it Alternating, uma string já alternada tem D=0 e exatamente uma sequência ótima, a sequência vazia.

Promova a multiplicação antes de avaliá-la. O código usa long long no acumulador e pressupõe módulo 998244353 e limite de 200.000: nessas condições f[i-1]*i cabe em 64 bits. Para vários testes, a tabela permite consultas O(1), mas não muda magicamente a complexidade total deste problema: como soma(N)≤200.000, calcular cada fatorial necessário separadamente também é linear na soma dos tamanhos. A tabela é uma opção de reutilização. Não há necessidade de o módulo ser primo para apenas multiplicar e tomar restos.

```cpp
vector<long long> fatoriaisModulo(int limite) {
    const long long MOD=998244353;
    assert(0<=limite && limite<=200000);
    vector<long long> f(limite+1,1);
    for (int i=2;i<=limite;++i) f[i]=f[i-1]*i%MOD;
    return f;
}
long long combinarEscolhasEOrdens(long long escolhas,int remocoes,
                                 const vector<long long>& fat) {
    const long long MOD=998244353;
    return (escolhas%MOD)*fat[remocoes]%MOD;
}
```

**Complexidade:** O(L) de tempo e espaço para pré-calcular até L; O(1) por consulta, além do tempo de analisar cada string.

**Critérios de acerto**

- Inicializar o produto vazio com 1.
- Reduzir depois de cada multiplicação e provar o limite do intermediário.
- Distinguir reutilização de tabela de uma melhora assintótica inexistente.

## cp-note-000091

**Pergunta**

Quando uma questão construtiva aceita qualquer solução ótima, como verificar a saída sem compará-la com uma string esperada? Aplique a Red Versus Blue.

**Resposta**

Verifique as propriedades exigidas: alfabeto permitido, quantidade de cada símbolo e valor do objetivo. Strings diferentes podem ser igualmente ótimas; compará-las literalmente com uma saída de exemplo rejeita soluções válidas.

Para Red Versus Blue, sob r>b≥1, o limite inferior do maior bloco é ceil(r/(b+1)), e a construção equilibrada já conhecida atinge esse limite. Portanto uma saída é ótima se tem exatamente r letras R, b letras B e seu maior bloco de qualquer símbolo tem esse valor. Conte também os blocos de B: validar só os de R não verifica toda a condição do problema.

Equilibrar todos os espaços é uma construção suficiente, mas não é necessário que toda solução ótima tenha seus tamanhos diferindo no máximo em 1. Com r=7 e b=2, os blocos 3,3,1 e 3,2,2 atingem o mesmo máximo ótimo 3. Este complemento separa provar a existência de uma construção de caracterizar todas as soluções possíveis.

```cpp
bool construcaoOtima(const string& s,int r,int b) {
    assert(r>b && b>=1);
    int reds=0,blues=0,pico=0,atual=0;
    char anterior='?';
    for (char c:s) {
        if (c!='R' && c!='B') return false;
        reds+=(c=='R'); blues+=(c=='B');
        atual=(c==anterior ? atual+1 : 1);
        pico=max(pico,atual); anterior=c;
    }
    int grupos=b+1;
    int limite=r/grupos+(r%grupos!=0);
    return reds==r && blues==b && pico==limite;
}
```

**Complexidade:** O(N) de tempo e O(1) de espaço; o limite inferior vem da prova matemática, não de uma busca pela saída exata.

**Critérios de acerto**

- Verificar validade, quantidades e o objetivo ótimo.
- Aceitar construções diferentes que atingem o mesmo limite.
- Não confundir uma construção suficiente com uma condição necessária.

## cp-note-000051

**Pergunta**

Como minimizar mudanças de um valor v quando cada elemento a[i] exige |v-a[i]|<=x? Por que manter a interseção de possibilidades é melhor que escolher v imediatamente?

**Resposta**

Cada elemento permite v no intervalo [a[i]-x,a[i]+x]. Enquanto a interseção dos intervalos do bloco é não vazia, algum mesmo v atende todos. Atualize o limite inferior pelo máximo e o superior pelo mínimo. Ao esvaziar, uma mudança é inevitável: nenhum v atende o bloco inteiro. Adiar a mudança até esse ponto maximiza o primeiro bloco e deixa o sufixo com o mesmo subproblema. A escolha inicial de v não conta como mudança.

Comparar só vizinhos não basta: com x=1 e a=[1,3,5], cada par adjacente permite algum v, mas os intervalos [0,2], [2,4] e [4,6] não têm interseção comum. O v=2 atende aos dois primeiros e v=4 aos dois últimos; não existe um único v para os três. Mantenha a interseção de todo o bloco.

```cpp
int mudancas(const vector<long long>& a,long long x) {
    long long L=a[0]-x,R=a[0]+x; int ans=0;
    for(long long v:a){
        long long l=v-x,r=v+x;
        if(max(L,l)>min(R,r)){++ans;L=l;R=r;}
        else {L=max(L,l);R=min(R,r);}
    }
    return ans;
}
```

**Complexidade:** O(n) de tempo e O(1) de espaço; array não vazio.

**Critérios de acerto**

- Explicar o invariante ou a justificativa do padrão.
- Reconstruir o uso em C++ e reconhecer as condições de validade.

## cp-note-000052

**Pergunta**

Como reorganizar índices dentro de grupos de valores iguais para que ninguém receba o próprio item? Quando a construção é impossível?

**Resposta**

Na entrada ordenada, valores iguais formam blocos. Um bloco de tamanho 1 não tem outro índice compatível: é impossível. Para cada bloco com pelo menos dois elementos, uma rotação cíclica dos índices cria uma permutação sem pontos fixos e mantém os valores iguais. No problema dos sapatos, todos precisam receber tamanho >=ao próprio; a soma dos tamanhos é preservada, então ninguém pode aumentar estritamente sem alguém diminuir. Portanto as trocas ficam entre tamanhos iguais.

Não substitua a rotação por trocas de pares disjuntos: um bloco de tamanho ímpar pode deixar alguém no próprio lugar. Em [5,5,5], trocar só os dois primeiros deixa o terceiro fixo; a rotação de índices [2,3,1] movimenta os três. Isso reforça por que a construção usa o bloco inteiro.

```cpp
vector<int> embaralhar(const vector<int>& a) {
    vector<int> p(a.size());
    for(int l=0;l<(int)a.size();){
        int r=l; while(r<(int)a.size() && a[r]==a[l]) ++r;
        if(r-l==1) return {};
        for(int i=l;i<r;++i) p[i]=(i+1<r ? i+2 : l+1);
        l=r;
    }
    return p;
}
```

**Complexidade:** O(n) de tempo e O(n) de espaço da permutação.

**Critérios de acerto**

- Explicar o invariante ou a justificativa do padrão.
- Reconstruir o uso em C++ e reconhecer as condições de validade.
