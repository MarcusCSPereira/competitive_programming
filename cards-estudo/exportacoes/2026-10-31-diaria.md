## cp-note-000092

**Pergunta**

Como o bit mais significativo ajuda a limitar o valor de a XOR b? Como achar a maior potência de dois até um inteiro sem log2 nem pow em C++17?

**Resposta**

XOR liga um bit exatamente quando os operandos diferem naquela posição. Logo o bit mais alto em que a e b diferem domina o valor do XOR: se essa posição vale K=2^k, então K≤(a XOR b)<2K. Os bits abaixo dela somam no máximo K-1. Em C++, ^ é XOR; não é exponenciação.

Se 0≤a<K e K≤b<2K, o bit de valor K difere e a XOR b é pelo menos K. Se ambos estão no mesmo lado desse corte e são menores que 2K, esse bit se cancela e o XOR fica abaixo de K. Essa divisão em grupos é o ponto central da construção de Roof Construction.

Para achar a maior potência de dois K≤x, dobre K enquanto o próximo dobro couber em x. A condição K≤x/2 evita testar 2*K antes de saber que a multiplicação cabe. O domínio é x≥1, aplicável a x=n-1 porque o problema garante n≥2. O laço inteiro evita depender de arredondamento de funções de ponto flutuante perto de potências de dois.

Há duas quantidades diferentes: o índice k=floor(log2(x)) do maior bit ligado e seu valor K=2^k. Para x=6, k=2 e K=4. O código retorna K diretamente; não retorna o índice. log2(x) sem o piso não é, em geral, um inteiro.

```cpp
int maiorPotenciaAte(int x) {
    assert(x>=1);
    int K=1;
    while (K<=x/2) K<<=1;
    return K;
}
bool ladosDiferentes(int a,int b,int K) {
    // Contrato: K é potência de dois e 0<=a,b<2*K.
    return ((a&K)!=0) != ((b&K)!=0);
}
```

**Complexidade:** O(log x) de tempo e O(1) de espaço. Os testes de bit e a operação XOR custam O(1) para inteiros da máquina.

**Critérios de acerto**

- Relacionar o maior bit diferente aos limites K e 2K do XOR.
- Distinguir ^ de exponenciação e & do teste de um bit.
- Dobrar com um limite inteiro seguro e tratar x≥1.

## cp-note-000093

**Pergunta**

Como construir uma permutação de 0 a n-1 que minimize o maior XOR entre vizinhos? Como provar um limite inferior e construir uma ordem que o atinge?

**Resposta**

O objetivo é minimizar max(p[i] XOR p[i+1]), considerando somente pares adjacentes. Isso não é maximizar o XOR nem aplicar XOR a todos os elementos juntos.

Seja K a maior potência de dois até n-1. Como K≤n-1<2K, os valores se dividem em [0,K-1], com o bit K desligado, e [K,n-1], com esse bit ligado. Os dois grupos são não vazios e qualquer permutação precisa atravessar entre eles em alguma adjacência. Esse par tem XOR≥K: nenhuma solução pode ter custo menor que K.

Para atingir o limite, emita K-1,K-2,…,0 e depois K,K+1,…,n-1. Dentro de cada grupo o bit K se cancela e o XOR é menor que K. Na única fronteira, os vizinhos são 0 e K, cujo XOR é exatamente K. Assim o custo máximo é K e a construção é ótima.

Não basta separar os grupos em qualquer ordem: a fronteira precisa ser bem escolhida. Para n=3, a ordem crescente [0,1,2] tem custo 3; [1,0,2] tem custo 2, o limite ótimo. O código inclui uma função para medir o objetivo em pares adjacentes e conferir a construção.

A prova usa uma travessia entre grupos em alguma adjacência. Não use o XOR acumulado de toda a permutação como limite: com n=4, 0^1^2^3=0, mas o menor custo máximo entre vizinhos é 2. São objetivos diferentes.

```cpp
vector<int> construirRoof(int n) {
    assert(n>=2);
    int K=1;
    while (K<=(n-1)/2) K<<=1;
    vector<int> p; p.reserve(n);
    for (int x=K-1;x>=0;--x) p.push_back(x);
    for (int x=K;x<n;++x) p.push_back(x);
    return p;
}
int custoRoof(const vector<int>& p) {
    int maior=0;
    for (int i=1;i<(int)p.size();++i) maior=max(maior,p[i-1]^p[i]);
    return maior;
}
```

**Complexidade:** O(n) de tempo para construir e medir. A saída ocupa O(n); a construção usa O(1) auxiliar além dela.

**Critérios de acerto**

- Provar que a travessia entre grupos impõe custo pelo menos K.
- Escolher uma fronteira de XOR exatamente K e limitar os pares internos.
- Verificar a permutação e o objetivo em vizinhos, sem confundir mínimo com máximo.

**Fontes**

- [Roof Construction · problemas · páginas 99, 100](https://codeforces.com/problemset/problem/1632/B)

## cp-note-000094

**Pergunta**

Há pontos em todos os lados de um retângulo de largura w e altura h. Como maximizar a área de um triângulo com exatamente dois vértices no mesmo lado? Como implementar sem testar todas as trincas?

**Resposta**

Fixando o lado que contém dois vértices, esses dois pontos formam a base. A maior base usa as duas coordenadas extremas desse lado. A altura é a distância perpendicular do terceiro vértice à reta da base, e não a distância até um extremo.

Para base horizontal, essa distância não passa de h e qualquer ponto do lado horizontal oposto atinge h. Para base vertical, use w. Como há pontos em todos os lados e nenhum é canto, sempre existe um terceiro vértice válido no lado oposto. Assim, para cada um dos quatro lados, a melhor área dobrada é (máximo−mínimo)×distância ao lado oposto. O máximo desses quatro candidatos é a resposta global. A coordenada do terceiro ponto ao longo do lado oposto não altera a altura.

A entrada já fornece as coordenadas em ordem crescente: bastam primeiro e último. O código guarda os extremos de cada lado, na ordem inferior, superior, esquerdo, direito. Durante a leitura, é possível descartar as coordenadas intermediárias. Se a lista não estiver ordenada, é necessário calcular mínimo e máximo.

Trabalhar com 2×área elimina a divisão por dois e preserva resultados sem arredondamento, inclusive quando a área é meio inteira. Use long long antes da multiplicação: com dimensões até 10^6, o produto pode se aproximar de 10^12 e ultrapassar int.

```cpp
long long maiorAreaDobrada(
     long long w, long long h,
     const array<pair<long long,long long>,4>& extremos) {
     // Cada par = {menor coordenada, maior coordenada} no lado.
     long long melhor=0;
     for (int lado=0;lado<4;++lado) {
         auto [menor,maior]=extremos[lado];
         long long base=maior-menor;
         long long altura=(lado<2 ? h : w);
         melhor=max(melhor,base*altura);
     }
     return melhor; // já é 2*área; não dividir por 2
 }
```

**Complexidade:** O(P) de tempo para ler P pontos e O(1) auxiliar guardando só quatro pares de extremos. Após a leitura, a função executa O(1) operações e usa O(1) espaço.

**Critérios de acerto**

- Justificar extremos na base e lado oposto para maximizar a altura.
- Associar bases horizontais a h e verticais a w.
- Usar área dobrada e multiplicação em 64 bits.

**Fontes**

- [Triangles on a Rectangle · problemas · páginas 101](https://codeforces.com/problemset/problem/1620/B)

## cp-note-000095

**Pergunta**

Como achar a maior sequência de valores inteiros consecutivos de um array não ordenado usando hash set, em tempo esperado O(n)? Por que os laços não tornam o algoritmo quadrático?

**Resposta**

A sequência é de valores: eles não precisam aparecer juntos nem ordenados no array. Construa um unordered_set para consultar presença e eliminar duplicatas. Um valor x só inicia uma sequência se x−1 não estiver no conjunto. A partir desse início, avance enquanto o próximo valor existir e atualize o maior comprimento.

Cada sequência maximal é percorrida uma vez, somente a partir do menor elemento. Os demais valores falham no teste de início. Somando todos os avanços, visitamos O(u) valores distintos, onde u≤n: dois laços aninhados não implicam O(n²) quando o trabalho interno total é linear. Com consultas de hash O(1) em média, o tempo total esperado é O(n). Colisões ruins podem degradá-lo; não é uma garantia de pior caso O(n). std::set usa O(log n) por consulta e não dá a mesma complexidade.

Itere o conjunto de valores distintos, não o array original: muitas cópias do início de uma sequência fariam repetir a mesma varredura. Para [100,4,200,1,3,2], a resposta é 4, pela sequência 1,2,3,4. Para array vazio, retorne zero.

O código promove os int a long long antes de calcular predecessor/sucessor, evitando overflow em INT_MIN−1 e INT_MAX+1. Essa proteção é um complemento didático: o enunciado restringe valores a ±10^9, mas a função abaixo também aceita todos os int.

```cpp
int maiorSequenciaConsecutiva(const vector<int>& nums) {
     unordered_set<long long> valores(nums.begin(),nums.end());
     int melhor=0;
     for (long long inicio:valores) {
         if (valores.count(inicio-1)) continue;
         long long atual=inicio;
         int tamanho=1;
         while (valores.count(atual+1)) {
             ++atual;
             ++tamanho;
         }
         melhor=max(melhor,tamanho);
     }
     return melhor;
 }
```

**Complexidade:** O(n) esperado de tempo, O(n) espaço; pior caso O(n²) se o hash se degradar. Contrato: entrada vector<int> de até 10^5 elementos; valores promovidos antes da aritmética.

**Critérios de acerto**

- Detectar somente o início usando ausência de x−1.
- Iterar valores únicos e justificar o total linear de avanços.
- Distinguir valores consecutivos de subarray e tempo esperado de pior caso.

## cp-note-000096

**Pergunta**

Como minimizar uma soma de frequências × distâncias ao distribuir prédios em coordenadas inteiras distintas? Por que os mais visitados ficam perto, e como devolver as coordenadas na ordem original?

**Resposta**

Podemos fixar a sede em x[0]=0, pois transladar todas as posições não muda as distâncias. As posições livres mais próximas são +1,−1,+2,−2,…: há dois lugares para cada distância positiva. Como as frequências são não negativas, usar posições mais distantes quando há uma mais próxima livre nunca melhora o custo. Frequência zero pode ocupar qualquer posição restante sem alterar o custo.

Ordene as frequências em ordem decrescente e atribua essas posições em ordem de distância crescente. A prova é por troca: se A≥B e d≤D, associar A a d e B a D custa A*d+B*D. A associação inversa custa A*D+B*d; a diferença é (A−B)*(D−d)≥0. Portanto eliminar inversões nunca piora a solução. O fator 2, pela ida e volta, multiplica todo o custo e não muda a ordenação ótima.

Guarde pares (frequência,índice original). Ordenar somente os valores perderia a identidade dos prédios: a saída precisa ser x[0],x[1],…,x[n], com cada prédio no seu índice inicial. No código, a posição escolhida é salva em x[id+1]. Use long long desde a multiplicação e na soma, pois 2*distância*frequência acumulado excede int. Empates podem ser resolvidos em qualquer ordem.

Esse argumento é um complemento didático derivado da solução local e do enunciado oficial; não foi encontrada uma anotação desta questão nos PDFs autorizados atuais.

```cpp
pair<long long,vector<int>> posicionarPredios(const vector<int>& visitas) {
     int n=(int)visitas.size();
     vector<pair<int,int>> ordem;
     for(int i=0;i<n;++i) ordem.push_back({visitas[i],i});
     sort(ordem.rbegin(),ordem.rend());
     vector<int> x(n+1,0); // sede no índice 0
     long long custo=0;
     for(int i=0;i<n;++i) {
         int distancia=i/2+1;
         int pos=(i%2==0 ? distancia : -distancia);
         auto [frequencia,id]=ordem[i];
         x[id+1]=pos;
         custo+=2LL*distancia*frequencia;
     }
     return {custo,x};
 }
```

**Complexidade:** O(n log n) de tempo e O(n) espaço. Para n≤200.000 e frequências≤10^6, coordenadas até 100.000 e custo até 20.000.200.000.000.000 cabem em long long.

**Critérios de acerto**

- Provar a escolha gulosa por troca de dois pesos/distâncias.
- Usar +1,−1,+2,−2,… e incluir ida e volta.
- Preservar índices originais e aritmética em 64 bits.
